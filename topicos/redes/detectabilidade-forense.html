Detectabilidade e Forense de Rede

Como identificar uso de proxies/VPNs e técnicas forenses para análise de tráfego.

🎯 Objetivos

Ao terminar, você será capaz de: identificar sinais de uso de proxies/VPNs em tráfego de rede, entender técnicas básicas de correlação de logs e tráfego, e conhecer ferramentas forenses essenciais (tcpdump, Wireshark, Zeek, Suricata).

⚡ Resumo Rápido

  • TTL Anomalies: VPNs/proxies alteram TTL dos pacotes — compare com baseline.
  • TCP/TLS Fingerprinting: Identificação de SO/cliente via padrões de handshake e cipher suites.
  • DNS Tunneling: Detectável por tamanho anormal de queries, alta frequência e entropia de subdomínios.
  • Port Knocking: Sequências de conexões a portas fechadas podem indicar covert channels.
  • Ferramentas: tcpdump/Wireshark (captura), Zeek/Suricata (IDS/análise), jq/awk (parsing de logs).

Identificando Uso de Proxies/VPNs

1. TTL (Time-to-Live) Anomalies

Cada pacote IP tem um campo TTL que é decrementado a cada salto (roteador). Sistemas operacionais usam valores iniciais padrão: Windows = 128, Linux = 64, macOS = 64.

Quando um usuário se conecta via VPN/proxy, o TTL é decrementado pelo túnel/proxy. Se você espera TTL ~60-64 (cliente Linux direto), mas recebe ~30-40, pode indicar intermediário.

# Capturar TTL com tcpdump: sudo tcpdump -i eth0 -n 'src host 192.168.1.100' -v | grep ttl # Analisar com tshark (Wireshark CLI): tshark -r capture.pcap -T fields -e ip.src -e ip.ttl | sort | uniq -c

Limitação: Nem sempre confiável; TTL pode variar por roteamento legítimo. Use como indicador, não prova absoluta.

2. TCP/TLS Fingerprinting

Cada sistema operacional e aplicação tem padrões únicos no handshake TCP e nas negociações TLS (ordem de cipher suites, extensões, tamanhos de janela). Ferramentas como p0f e JA3 (para TLS) criam "fingerprints" identificáveis.

Se o fingerprint TLS indica "Cliente Linux com OpenSSL 1.1.1", mas o user-agent HTTP diz "Windows 10 com Chrome", há inconsistência suspeita (possível proxy/VPN intermediário modificando tráfego).

# p0f (passive OS fingerprinting): sudo p0f -i eth0 -p -o /tmp/p0f.log # JA3 fingerprint (requer Zeek ou script Python): # Zeek gera JA3 automaticamente em ssl.log zeek -i eth0 -C local cat ssl.log | zeek-cut ja3 ja3s

3. Listas de IPs Conhecidos de VPN/Proxy

Existem bancos de dados públicos de IPs de provedores de VPN (NordVPN, ExpressVPN, etc.) e proxies públicos. Comparar IPs de origem com essas listas é método rápido, mas requer atualização constante.

Serviços: IPHub, IP2Proxy, MaxMind GeoIP2 Anonymous IP.

4. Port Knocking & Anomalias de Porta

Port knocking é técnica onde cliente envia sequência específica de conexões a portas fechadas antes de acessar porta real (covert channel). Detectável por padrões repetidos de SYN a portas fechadas em curto espaço de tempo.

# Detectar port scans/knocking com tcpdump: sudo tcpdump -i eth0 'tcp[tcpflags] & tcp-syn != 0 and tcp[tcpflags] & tcp-ack == 0' -n # Ou com iptables logging: iptables -A INPUT -p tcp --dport 1000:9000 -j LOG --log-prefix "PORT_KNOCK: "

Detectando DNS Tunneling & Exfiltração

DNS tunneling usa queries DNS para encapsular dados arbitrários (ex: comandos C2, exfiltração de arquivos). Ferramentas como Iodine e dnscat2 fazem isso.

Sinais de DNS Tunneling

  • Queries muito longas: Subdomínios com 50+ caracteres (dados codificados em base64/hex).
  • Alta frequência: Centenas de queries para mesmo domínio em curto período.
  • Alta entropia: Subdomínios parecem aleatórios (ex: a8f3b2c9d1e4.evil.com).
  • Tipos de registro incomuns: Uso excessivo de TXT, NULL ou registros raros.
# Capturar DNS queries com tcpdump: sudo tcpdump -i eth0 port 53 -w dns.pcap # Analisar com tshark: tshark -r dns.pcap -Y "dns.qry.name" -T fields -e dns.qry.name | sort | uniq -c | sort -rn # Calcular entropia de subdomínios (script Python/awk): # Subdomínios com entropia > 3.5 são suspeitos

Cenário: SOC detecta exfiltration via DNS tunneling ao observar queries de 60 caracteres com alta entropia para domínio externo, em volume de 500 queries/min.

Logs e Monitoramento: O Que Registrar

Dados Essenciais para Forense

  • Connection tracking (conntrack): IP origem/destino, portas, protocolo, duração, bytes transferidos.
  • Logs de Proxy: User, timestamp, URL acessada, método HTTP, status code, tamanho de resposta, user-agent.
  • Logs de Firewall: Pacotes aceitos/bloqueados, regra acionada, flags TCP.
  • DNS logs: Query, resposta, cliente, servidor DNS consultado.
  • TLS/SSL logs: Cipher suites negociadas, versão TLS, SNI (Server Name Indication), JA3 fingerprint.

Correlação Básica de Logs

Correlacionar eventos de diferentes fontes (firewall + proxy + DNS) por timestamp e IP de origem. Por exemplo:

  1. Firewall registra conexão de 192.168.1.50 para 1.2.3.4:443.
  2. Proxy registra 192.168.1.50 acessando https://suspicious.com.
  3. DNS log mostra 192.168.1.50 consultou suspicious.com 2 segundos antes.

Timeline completa permite rastrear origem e destino de incidentes.

# Extrair IPs de múltiplos logs e correlacionar com jq/grep: grep "192.168.1.50" /var/log/firewall.log grep "192.168.1.50" /var/log/proxy/access.log grep "192.168.1.50" /var/log/named/queries.log # Usar awk para parsing e join por timestamp: awk '{print $1, $2, $5}' firewall.log > fw.tmp awk '{print $1, $2, $7}' proxy.log > proxy.tmp join -j 1 fw.tmp proxy.tmp

🛠️ Ferramentas Forenses Essenciais

tcpdump

Captura de pacotes em linha de comando. Leve, rápido, ideal para captura remota via SSH.

sudo tcpdump -i eth0 -n -s0 -w capture.pcap sudo tcpdump -i eth0 port 443 -A
Captura CLI

Wireshark / tshark

Análise profunda de pacotes com GUI (Wireshark) ou CLI (tshark). Suporta centenas de protocolos, filtros avançados.

wireshark capture.pcap tshark -r capture.pcap -Y "http.request"
Análise GUI/CLI

Zeek (antigo Bro)

IDS/Network Security Monitor que gera logs estruturados (JSON) de conexões, HTTP, DNS, SSL/TLS. Altamente extensível via scripts.

zeek -i eth0 -C local cat conn.log | zeek-cut id.orig_h id.resp_h service duration
IDS Logs Estruturados

Suricata

IDS/IPS multi-threaded com suporte a regras Snort. Gera alertas e logs detalhados, compatível com Zeek para correlação.

sudo suricata -c /etc/suricata/suricata.yaml -i eth0 tail -f /var/log/suricata/fast.log
IDS/IPS Regras

p0f

Passive OS fingerprinting. Identifica SO e aplicação sem enviar pacotes, apenas analisando tráfego observado.

sudo p0f -i eth0 -p -o /tmp/p0f.log
Fingerprinting Passivo

jq / awk / grep

Ferramentas CLI para parsing e análise de logs (JSON, texto). Essenciais para correlação rápida.

cat conn.log | jq '.id.orig_h' | sort | uniq -c grep "192.168.1" access.log | awk '{print $7}'
Parsing CLI

📋 Cenários Práticos

Cenário 1: Detecção de Exfiltração via DNS Tunneling

Situação: Analista do SOC nota volume anormal de queries DNS para domínio externo c2server.xyz.
Análise: Captura com tcpdump mostra subdomínios de 60+ caracteres com alta entropia, 500 queries/min.
Ação: Bloquear domínio no firewall/DNS, isolar máquina comprometida, investigar origem (malware, insider threat).
Ferramenta: Zeek + script de cálculo de entropia + análise manual com Wireshark.

Cenário 2: Identificação de VPN Corporativa Não Autorizada

Situação: Política proíbe VPNs pessoais. Firewall detecta tráfego OpenVPN (porta 1194/UDP) de workstation interna.
Análise: TLS fingerprint confirma OpenVPN client. TTL inconsistente (esperado 64, recebido 50) indica túnel.
Ação: Bloquear porta 1194/UDP, confrontar usuário, aplicar política de segurança.
Ferramenta: Firewall logs + p0f + Zeek SSL logs.

Cenário 3: Investigação de Port Knocking Suspeito

Situação: IDS alerta sobre sequência repetida de SYN para portas fechadas (1234, 5678, 9012) de IP externo.
Análise: Após sequência, conexão SSH (porta 22) é estabelecida. Port knocking para backdoor SSH.
Ação: Bloquear IP de origem, revisar regras de firewall, buscar backdoor no servidor.
Ferramenta: Suricata (custom rule) + iptables logging + correlação manual.

📚 Glossário

TTL (Time-to-Live)
Campo IP que limita número de saltos de um pacote; decrementado a cada roteador.
JA3 Fingerprint
Hash MD5 de características do handshake TLS; identifica cliente/biblioteca TLS.
DNS Tunneling
Técnica de encapsular dados em queries/respostas DNS para evadir firewall.
Port Knocking
Sequência de conexões a portas fechadas para abrir porta de serviço (covert channel).
Conntrack
Connection tracking; registro de conexões ativas/históricas no firewall/sistema.
Zeek (Bro)
Network Security Monitor que gera logs estruturados de protocolos (HTTP, DNS, SSL, etc).
p0f
Ferramenta de passive OS fingerprinting via análise de padrões TCP/IP.
