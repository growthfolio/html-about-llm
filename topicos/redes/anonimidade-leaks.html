Anonimidade e Leaks: Problemas e Mitigação

Checklist completo de vazamentos comuns e como proteger-se.

Objetivos de Aprendizagem

Ao terminar, você saberá identificar e mitigar DNS leaks, WebRTC leaks, IPv6 leaks, browser fingerprinting e compreenderá técnicas de de-anonimização.

Resumo Rápido

  • DNS leak: Consultas DNS vão para ISP em vez de passar pela VPN/Tor.
  • WebRTC leak: JavaScript expõe IP real mesmo com VPN ativa.
  • IPv6 leak: VPN só tunela IPv4, tráfego IPv6 vai direto.
  • Browser fingerprinting: Combinação de user-agent, plugins, resolução, timezone identifica você.
  • Kill-switch: Bloqueia tráfego se VPN/Tor cair.

DNS Leaks

Mesmo com VPN/Tor ativo, seu sistema pode continuar enviando consultas DNS diretamente para os servidores do ISP (geralmente configurados via DHCP). Isso revela quais domínios você acessa.

Cenário:

Usuário ativa VPN para privacidade, mas o SO continua usando DNS do ISP (8.8.8.8 ou DNS local). ISP consegue registrar todos os domínios visitados, anulando benefício da VPN.

Mitigação:

  • Configurar DNS over HTTPS (DoH): Firefox/Chrome suportam nativamente (Cloudflare 1.1.1.1, Google 8.8.8.8).
  • Usar DNS do provedor VPN: Garantir que VPN configura DNS automaticamente (push DNS via DHCP).
  • Forçar DNS via firewall: iptables -A OUTPUT -p udp --dport 53 -j REJECT (bloqueia DNS fora da VPN).
  • Verificar leak: https://dnsleaktest.com/

WebRTC Leaks

WebRTC (Web Real-Time Communication) é uma API de navegador para vídeo/áudio P2P. Para estabelecer conexões diretas, ele expõe o IP local e público real, mesmo através de VPN.

Cenário:

Usuário visita site malicioso com VPN ativa. JavaScript do site usa WebRTC para descobrir IP real do usuário, identificando-o.

Mitigação:

  • Desabilitar WebRTC no navegador:
    • Firefox: about:config → media.peerconnection.enabled = false
    • Chrome: Usar extensão "WebRTC Leak Prevent" ou "uBlock Origin" (modo avançado).
  • Usar Tor Browser: WebRTC já vem desabilitado por padrão.
  • Verificar leak: https://browserleaks.com/webrtc

IPv6 Leaks

Muitas VPNs só tunelam tráfego IPv4. Se seu ISP e o site de destino suportam IPv6, o tráfego pode ir direto sem passar pela VPN, expondo seu IP.

Cenário:

Usuário com IPv6 ativo conecta a VPN antiga que não suporta IPv6. Ao acessar site com IPv6, conexão vai direto pelo ISP.

Mitigação:

  • Desabilitar IPv6: Temporariamente ou permanentemente no SO.
    • Linux: sudo sysctl -w net.ipv6.conf.all.disable_ipv6=1
    • Windows: Desmarcar "Internet Protocol Version 6" nas propriedades da interface de rede.
  • Usar VPN com suporte IPv6: Provedores modernos (Mullvad, IVPN) tunelam IPv6.
  • Verificar leak: https://test-ipv6.com/ ou https://ipleak.net/

VPN/Proxy Kill-Switch

Se a VPN cai inesperadamente (reconexão, falha de servidor), o tráfego pode voltar a usar a rota padrão (ISP), expondo atividade. Um kill-switch bloqueia todo o tráfego se a VPN não estiver ativa.

Implementação:

  • Cliente VPN nativo: A maioria dos apps VPN (NordVPN, ProtonVPN) tem opção kill-switch embutida.
  • Firewall manual (Linux com iptables): 
    # Permitir apenas tráfego pela interface VPN (tun0)
iptables -P OUTPUT DROP
iptables -A OUTPUT -o tun0 -j ACCEPT
iptables -A OUTPUT -o lo -j ACCEPT
iptables -A OUTPUT -d VPN_SERVER_IP -j ACCEPT  # Permitir conexão ao servidor VPN
  • WireGuard: Configurar PostDown hook para bloquear tráfego se interface cair.

Browser Fingerprinting

Combinação de atributos do navegador (user-agent, plugins, fontes instaladas, resolução de tela, timezone, canvas rendering) cria uma "impressão digital" única que identifica você mesmo sem cookies.

Vetores de fingerprinting:

  • Canvas fingerprinting: Renderiza imagem invisível; mínimas diferenças de hardware criam hash único.
  • Font enumeration: JavaScript lista fontes instaladas (cada combo é raro).
  • WebGL/GPU info: Expõe modelo de GPU.
  • Battery API: Nível de bateria + tempo de carga = identificador temporário.

Mitigação:

  • Usar Tor Browser: Todos os usuários têm fingerprint idêntico (resistência ativa).
  • Extensões: uBlock Origin (modo avançado), Privacy Badger, Canvas Blocker.
  • Configuração manual: Desabilitar JavaScript em sites não-confiáveis, usar private browsing mode.
  • Evitar plugins: Flash, Java, PDF plugins aumentam superfície de fingerprinting.
  • Verificar fingerprint: https://amiunique.org/ ou https://coveryourtracks.eff.org/

TLS Fingerprinting

Diferentes clients (browsers, apps) enviam diferentes conjuntos de cipher suites, extensões e versões TLS no handshake inicial. Isso cria uma "assinatura TLS" que pode identificar navegador/OS.

Mitigação:

  • Usar Tor Browser: TLS fingerprint padronizado.
  • Awareness: Difícil de mitigar manualmente; usar software atualizado e popular (Firefox, Chrome) torna você "comum" no fingerprint.
  • Verificar: https://www.ssllabs.com/ssltest/viewMyClient.html

Técnicas de De-anonymization

Adversários avançados (agências estatais, ISPs) têm técnicas sofisticadas:

  • Timing Attacks: Correlacionar timestamps de pacotes entrando e saindo de nós Tor/VPN para identificar usuário (requer controle de múltiplos pontos).
  • Traffic Correlation: Analisar padrões de volume/timing de tráfego. Ex: se único usuário acessa VPN às 2AM e site X recebe visita anônima às 2AM, correlação probabilística é alta.
  • Website Fingerprinting: Machine learning para identificar sites visitados via Tor analisando padrões de tamanho/timing de pacotes criptografados.
  • Browser Exploits: Zero-days para explorar navegadores e deanonymizar (ex: FBI vs. Tor em operações criminais).

Defesa: Não existe proteção 100%. Combinar camadas (Tor + VPN + Tails + boas práticas) dificulta, mas não elimina risco contra adversários de estado-nação.

Checklist de Anonimidade

Use esta lista para revisar sua configuração:

  • VPN/Tor ativo e verificado (https://ipleak.net/)
  • DNS configurado para passar pela VPN/Tor (teste em dnsleaktest.com)
  • WebRTC desabilitado ou mitigado
  • IPv6 desabilitado ou tunelado pela VPN
  • Kill-switch configurado
  • Navegador resistente a fingerprinting (Tor Browser ou Firefox hardened)
  • JavaScript desabilitado em sites não-confiáveis (NoScript)
  • Sem plugins/extensões desnecessárias
  • Sem login em contas reais durante atividade anônima
  • Timezone do sistema em UTC (reduz fingerprinting)

Glossário Rápido

DNS Leak:
Consultas DNS vão para ISP em vez de VPN/Tor.
WebRTC Leak:
API de navegador que expõe IP real via JavaScript.
Kill-Switch:
Mecanismo que bloqueia internet se VPN cair.
Browser Fingerprinting:
Identificação via combinação de atributos do navegador.
Traffic Correlation:
Técnica de análise de timing/volume para deanonymizar.
