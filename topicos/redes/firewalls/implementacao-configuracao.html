Implementação e Configuração de Firewalls

Transformando a teoria em prática: protegendo sua rede com regras e políticas.

Zonas de Segurança: Segmentando a Rede

A forma como organizamos a rede é fundamental para a segurança. Firewalls são usados para criar e impor limites entre diferentes "zonas de segurança", cada uma com seu próprio nível de confiança e políticas de acesso.

Rede Interna (LAN)

A zona mais confiável, onde estão os recursos críticos da organização e os usuários internos.

DMZ (Zona Desmilitarizada)

Uma zona intermediária, menos confiável que a interna, mas mais confiável que a internet. Abriga servidores públicos (web, e-mail) que precisam ser acessíveis externamente, mas que, se comprometidos, não dão acesso direto à rede interna.

Rede Externa (Internet)

A zona de menor confiança, considerada hostil e não confiável. Todas as conexões provenientes dela são tratadas com desconfiança.

Criação de Políticas e Regras de Firewall

A segurança de um firewall é definida por suas regras. Uma política de firewall é um conjunto de regras que determinam o que é permitido e o que é bloqueado. A ordem das regras é crucial.

Princípio do "Implicit Deny" (Negação Implícita)

A melhor prática em segurança de firewall é "negar tudo que não for explicitamente permitido". A última regra em qualquer firewall deve ser sempre um deny all (negar tudo), garantindo que nada passe sem uma permissão explícita.

Estrutura de uma Regra

As regras geralmente especificam:

  • Origem: Endereço IP/rede, zona.
  • Destino: Endereço IP/rede, zona.
  • Serviço/Porta: Ex: HTTP (porta 80), HTTPS (porta 443).
  • Ação: Permitir (Allow) ou Negar (Deny).

Exemplo de Regras (Conceitual)

# Regras de Alto Nível (Permitir o essencial)
PERMITIR TCP de Rede Interna para DMZ na Porta 80 (Acesso ao servidor web)
PERMITIR TCP de Rede Interna para Internet nas Portas 80, 443 (Navegação Web)

# Regras de Baixo Nível (Restrições específicas)
NEGAR UDP de Internet para Rede Interna na Porta 137 (Evitar ataques NetBIOS)

# Regra Final (Negação Implícita)
NEGAR TODO O TRÁFEGO QUE NÃO CORRESPONDER A UMA REGRA ANTERIOR

NAT (Network Address Translation) em Firewalls

NAT é um mecanismo que permite que múltiplos dispositivos com endereços IP privados compartilhem um ou poucos endereços IP públicos para acessar a internet. O firewall é o local comum onde o NAT é implementado.

NAT Estático (Static NAT)

Um endereço IP privado é mapeado para um endereço IP público fixo. Útil para servidores internos que precisam estar sempre acessíveis de fora por um IP público específico.

NAT Dinâmico (Dynamic NAT)

Um pool de endereços IP públicos é usado. Quando um dispositivo interno precisa acessar a internet, ele recebe um IP público disponível do pool.

PAT (Port Address Translation) ou NAT de Sobrecarga

A forma mais comum de NAT. Múltiplos endereços IP privados são mapeados para um ÚNICO endereço IP público, mas usando diferentes portas para distinguir as conexões. É o que acontece na maioria das redes domésticas.

Firewall de Borda vs. Firewall de Host

Firewalls podem ser implementados em diferentes pontos da rede para fornecer camadas de proteção.

Firewall de Borda (Perimeter Firewall)

Protege toda a rede, situado na fronteira entre a rede interna e a internet. É a primeira linha de defesa, protegendo múltiplos dispositivos de uma só vez.

Firewall de Host (Host-based Firewall)

Instalado diretamente em um computador individual (ex: Firewall do Windows, iptables no Linux). Protege especificamente aquele host, adicionando uma camada extra de segurança, mesmo que o firewall de borda falhe ou que o host esteja em uma rede não protegida.
