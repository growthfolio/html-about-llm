Tunelamento Avançado e Pluggable Transports

SSH tunnels, DNS/ICMP tunneling e técnicas para evadir censura.

Objetivos de Aprendizagem

Ao terminar, você saberá criar túneis SSH (local/remote/dynamic), usar DNS/ICMP tunneling para contornar firewalls e entender pluggable transports para evasão de censura.

Resumo Rápido

  • SSH Local Forwarding: ssh -L local_port:dest:dest_port user@server
  • SSH Remote Forwarding: ssh -R remote_port:dest:dest_port user@server
  • SSH Dynamic Forwarding (SOCKS5): ssh -D 1080 user@server
  • DNS tunneling: Encapsula dados em queries DNS (útil quando apenas DNS é permitido).
  • Pluggable transports: Disfarçam tráfego proibido (Tor) como permitido (HTTPS, WebRTC).

SSH Tunneling

SSH não é apenas para acesso remoto; pode criar túneis criptografados para encaminhar tráfego de forma segura através de redes não-confiáveis.

Local Port Forwarding (-L)

Encaminha porta local para um destino via servidor SSH intermediário.

# Sintaxe: ssh -L [bind_address:]local_port:destination:destination_port user@ssh_server # Exemplo: acessar banco de dados interno via bastion ssh -L 3306:db.internal.corp:3306 user@bastion.corp.com # Agora: mysql -h 127.0.0.1 -P 3306 se conecta ao db.internal.corp via túnel SSH

Caso de uso: Acessar serviços internos (DB, web apps) de forma segura sem expor diretamente à internet.

Remote Port Forwarding (-R)

Expõe porta do servidor remoto para acessar serviço local (túnel reverso).

# Sintaxe: ssh -R [bind_address:]remote_port:destination:destination_port user@ssh_server # Exemplo: expor app local (localhost:8000) na porta 8080 do servidor remoto ssh -R 8080:localhost:8000 user@remote.example.com # Qualquer um que acessar remote.example.com:8080 será redirecionado para seu localhost:8000

Caso de uso: Demonstrar app local para cliente externo sem deploy, ou contornar NAT/firewall (reverse shell legítimo).

Dynamic Port Forwarding (-D) — SOCKS5 Proxy

Cria um proxy SOCKS5 local que encaminha qualquer tráfego via servidor SSH.

# Sintaxe: ssh -D [bind_address:]local_port user@ssh_server # Exemplo: criar SOCKS5 proxy em localhost:1080 ssh -D 1080 user@bastion.example.com # Configurar navegador/app para usar SOCKS5 proxy em 127.0.0.1:1080 # Todo o tráfego sai do bastion, não do seu IP local

Caso de uso: Contornar firewall corporativo, acessar recursos geo-restritos via servidor em outra região.

Cenário combinado:

Desenvolvedor remoto usa ssh -L para acessar DB de produção via bastion, e ssh -D para rotear tráfego web via servidor da empresa.

HTTP CONNECT Tunneling

O método HTTP CONNECT foi criado para permitir tráfego HTTPS via proxies HTTP. Ele estabelece um túnel TCP "cru" através do proxy, permitindo passar qualquer protocolo.

# Usar SSH através de proxy HTTP (corkscrew ou nc + ProxyCommand) # Instalar corkscrew: apt-get install corkscrew # ~/.ssh/config: Host restricted-server Hostname server.example.com ProxyCommand corkscrew proxy.corp.com 8080 %h %p User myuser # Conectar normalmente: ssh restricted-server

Caso de uso: Ambiente corporativo onde apenas proxy HTTP (porta 8080) é permitido; tunela SSH através dele.

DNS Tunneling

Encapsula dados arbitrários em queries e respostas DNS. Útil quando firewall bloqueia tudo exceto DNS (porta 53 UDP/TCP). Muito lento, mas eficaz para contornar censura extrema.

Como funciona:

  1. Cliente codifica dados em subdomain (ex: data123.tunnel.example.com).
  2. Query DNS é enviada; servidor autoritativo para tunnel.example.com decodifica.
  3. Resposta DNS contém dados codificados (TXT records, CNAME, etc).

Ferramenta: Iodine

# Servidor (precisa de domínio + servidor DNS autoritativo): sudo iodined -f -c -P senha 10.0.0.1 tunnel.example.com # Cliente: sudo iodine -f -P senha tunnel.example.com # Interface tun criada (dns0); rotear tráfego via 10.0.0.1

Performance: ~3-50 KB/s (muito lento), alta latência. Útil apenas para texto/comandos, não para streaming.

Cenário:

Pentester em rede corporativa restrita exfiltra dados via DNS tunneling, já que firewall só permite DNS.

ICMP Tunneling

Encapsula dados em pacotes ICMP Echo Request/Reply (ping). Firewalls geralmente permitem ICMP para diagnóstico, criando vetor de exfiltração.

Ferramenta: ptunnel

# Servidor: sudo ptunnel # Cliente (tunela porta SSH local via ICMP para servidor remoto): sudo ptunnel -p proxy.example.com -lp 8000 -da remote.internal -dp 22 # Conectar: ssh -p 8000 localhost (vai via ICMP para remote.internal:22)

Detecção: IDS/IPS modernos detectam ICMP anômalo (payload não-padrão, alto volume). Uso deve ser cauteloso.

Pluggable Transports (Evasão de Censura)

Desenvolvidos para Tor, pluggable transports disfarçam tráfego proibido para parecer tráfego legítimo, contornando DPI (Deep Packet Inspection) e bloqueios de protocolo.

obfs4 (Obfuscation 4)

Randomiza tráfego Tor para evitar detecção de padrões. Adiciona ruído aleatório e timing variations.

# Configurar Tor com obfs4 (já visto em página Tor): UseBridges 1 ClientTransportPlugin obfs4 exec /usr/bin/obfs4proxy Bridge obfs4 IP:PORT FINGERPRINT cert=...

meek (Domain Fronting)

Tunela tráfego via domínios permitidos (CDNs grandes como Azure, CloudFront). Firewall vê HTTPS para microsoft.com, não Tor.

Limitação: Azure/Google bloquearam domain fronting em 2018; meek agora usa fallback methods.

Snowflake

Cria proxies temporários usando WebRTC em navegadores de voluntários. Cliente Tor conecta a um "snowflake proxy" efêmero; muito difícil de bloquear (IPs mudam constantemente).

# Ativar Snowflake no Tor Browser: # Settings → Connection → Use a bridge → Select "Snowflake" # Voluntariar-se como proxy: # Instalar extensão Snowflake no Firefox/Chrome

Cenário:

Ativista em país com censura pesada usa Snowflake bridges para acessar Tor sem ser detectado pelo Great Firewall.

TLS/SSL Tunneling (stunnel)

Encapsula protocolos não-criptografados dentro de TLS, fazendo-os parecer HTTPS. Útil para proteger protocolos legados ou passar por firewalls que só permitem HTTPS.

# Servidor stunnel (encapsula serviço local não-criptografado): # /etc/stunnel/stunnel.conf: [service] accept = 443 connect = 127.0.0.1:8080 cert = /etc/stunnel/cert.pem key = /etc/stunnel/key.pem # Cliente stunnel: [service] client = yes accept = 127.0.0.1:8080 connect = server.example.com:443 # App local conecta a localhost:8080, tráfego vai criptografado via TLS para server:443

Caso de uso: Proteger tráfego HTTP legado, ou passar firewall que bloqueia tudo exceto porta 443.

Glossário Rápido

Port Forwarding:
Redirecionamento de porta para outro destino via intermediário.
SOCKS5 Proxy:
Proxy versátil que suporta TCP/UDP; criado com ssh -D.
DNS Tunneling:
Encapsular dados em queries DNS para contornar firewalls.
Pluggable Transport:
Técnica para disfarçar tráfego proibido (obfs4, meek, Snowflake).
Domain Fronting:
Técnica de usar CDN para esconder destino real de requisição HTTPS.
