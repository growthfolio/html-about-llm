Protocolos de VPN: Comparativo Prático

IPSec, OpenVPN, WireGuard: entenda as diferenças, trade-offs e quando usar cada um.

Objetivos de Aprendizagem

Ao terminar, você será capaz de escolher o protocolo VPN adequado para cada cenário, entender trade-offs de performance/segurança e configurar exemplos básicos.

Resumo Rápido

  • IPSec: Padrão corporativo para site-to-site, complexo mas robusto.
  • OpenVPN: Maduro, baseado em SSL/TLS, amplamente suportado, configurável.
  • WireGuard: Moderno, simples, rápido, código auditável (~4k linhas vs ~100k do OpenVPN).
  • Split tunneling: Apenas tráfego específico vai pela VPN; full-tunneling envia tudo.
  • Comando útil: wg-quick up wg0 ativa interface WireGuard.

IPSec (Internet Protocol Security)

IPSec é um conjunto de protocolos que opera na camada de rede (Layer 3), criptografando pacotes IP. É o padrão de facto para VPNs corporativas site-to-site, mas também usado em client-to-site.

Características:

  • Modos: Tunnel mode (criptografa pacote inteiro, usado em VPNs) e Transport mode (criptografa apenas payload).
  • Protocolos: ESP (Encapsulating Security Payload) para confidencialidade e AH (Authentication Header) para autenticidade.
  • Key Management: IKE (Internet Key Exchange) negocia chaves; IKEv2 é a versão moderna, mais rápida e resistente a desconexões (ideal para mobile).
  • Complexidade: Configuração verbosa, múltiplas fases de negociação, difícil troubleshooting.

Quando usar:

Site-to-site entre escritórios, integração com hardware dedicado (firewalls Cisco, Fortinet), compliance corporativo.

Cenário:

Empresa multinacional conecta matriz e 20 filiais usando IPSec site-to-site em firewalls Cisco ASA, com failover automático.

OpenVPN

OpenVPN usa SSL/TLS para autenticação e criptografia, operando sobre UDP ou TCP. É altamente configurável e funciona em quase qualquer plataforma.

Características:

  • Baseado em SSL/TLS: Usa bibliotecas criptográficas maduras (OpenSSL, mbed TLS).
  • Flexibilidade: Suporta certificate-based auth, username/password, 2FA, configuração via arquivos .ovpn.
  • UDP vs TCP: UDP (porta 1194) é mais rápido; TCP (porta 443) útil para bypass de firewalls (parece HTTPS).
  • Overhead: Maior latência que WireGuard devido à complexidade do protocolo.

Quando usar:

Clientes remotos acessando rede corporativa, ambientes multi-plataforma (Windows, Linux, macOS, Android, iOS), quando precisa de compatibilidade máxima.

# Exemplo de configuração cliente OpenVPN (.ovpn) client dev tun proto udp remote vpn.example.com 1194 resolv-retry infinite nobind persist-key persist-tun ca ca.crt cert client.crt key client.key cipher AES-256-GCM auth SHA256 verb 3 # Conectar: sudo openvpn --config client.ovpn

Cenário:

Startup de 200 funcionários remotos usa OpenVPN Access Server com 2FA (Google Authenticator) para acesso à rede interna.

WireGuard

WireGuard é o mais novo (2020 no kernel Linux), desenhado para ser simples, rápido e seguro. Usa criptografia moderna (ChaCha20, Curve25519) e tem código mínimo auditável.

Características:

  • Performance: Muito mais rápido que OpenVPN e IPSec; menor latência, maior throughput.
  • Simplicidade: Configuração minimalista (~10 linhas), baseada em public/private keypairs.
  • Criptografia moderna: Noise Protocol Framework, sem negociação complexa de cipher suites.
  • Stateless: Não mantém estado de conexão, reconecta instantaneamente (ideal para mobile).
  • Trade-off: Requer IP estático ou DNS dinâmico para peers; menos features que OpenVPN (sem user/pass nativo).

Quando usar:

Conexões ponto-a-ponto de alta performance, ambientes cloud (AWS, GCP), mobile workers, quando simplicidade e velocidade são prioridade.

# Configuração WireGuard Server (/etc/wireguard/wg0.conf) [Interface] Address = 10.0.0.1/24 ListenPort = 51820 PrivateKey = PostUp = iptables -A FORWARD -i wg0 -j ACCEPT PostDown = iptables -D FORWARD -i wg0 -j ACCEPT [Peer] PublicKey = AllowedIPs = 10.0.0.2/32 # Ativar: sudo wg-quick up wg0 # Configuração Cliente [Interface] Address = 10.0.0.2/24 PrivateKey = DNS = 1.1.1.1 [Peer] PublicKey = Endpoint = vpn.example.com:51820 AllowedIPs = 0.0.0.0/0 # Full tunneling PersistentKeepalive = 25 # Conectar: sudo wg-quick up wg0

Cenário:

Freelancer usa WireGuard para conectar laptop e celular ao servidor home, com roaming automático entre WiFi e 4G sem interrupção.

Arquiteturas de VPN

Client-to-Site (Remote Access)

Usuário remoto conecta-se à rede corporativa. Protocolo comum: OpenVPN, IKEv2, WireGuard.

Site-to-Site

Conecta duas redes inteiras (ex: matriz ↔ filial). Protocolo comum: IPSec, WireGuard em gateways.

Mesh VPN

Cada nó conecta-se a todos os outros. Usado em infraestruturas distribuídas (Kubernetes clusters, multi-cloud). Ferramentas: Tailscale, Nebula, ZeroTier.

Cloud VPN (Managed)

AWS VPN, GCP Cloud VPN, Azure VPN Gateway — serviços gerenciados que abstraem configuração de IPSec.

Conceitos Avançados

  • Split-tunneling: Apenas tráfego para redes específicas vai pela VPN (ex: apenas 10.0.0.0/8); resto vai direto pela internet. Economiza banda e latência.
  • Full-tunneling: Todo o tráfego passa pela VPN. Mais seguro, mas pode ser mais lento.
  • MTU/Overhead: VPNs adicionam headers (encapsulamento), reduzindo MTU efetivo. Configurar MTU correto evita fragmentação e melhora performance.
  • Key Management: Certificate-based (PKI com CA) vs keypair (WireGuard). Rotação de chaves é critical para segurança de longo prazo.
  • Multi-hop VPNs: Encadear VPNs (VPN1 → VPN2) para distribuir confiança, mas com penalidade de latência.

Privacy Trade-offs

VPNs comerciais (NordVPN, ProtonVPN, Mullvad) prometem privacidade, mas considere:

  • Logging policies: Verifique se guardam logs de conexão, DNS queries, IPs. Preferir "no-log" auditados.
  • Jurisdição: País onde a empresa está sediada (14 Eyes intelligence alliance, GDPR, etc).
  • Chaining VPNs: Usar duas VPNs sequencialmente distribui confiança, mas duplica latência.
  • VPN Kill-switch: Bloqueia tráfego se VPN cair, evitando leaks acidentais.

Glossário Rápido

IKE (Internet Key Exchange):
Protocolo que negocia chaves criptográficas para IPSec.
ESP (Encapsulating Security Payload):
Parte do IPSec que criptografa o payload.
MTU (Maximum Transmission Unit):
Tamanho máximo de pacote; VPN reduz devido ao overhead de encapsulamento.
Split-tunneling:
Apenas tráfego selecionado vai pela VPN; resto vai direto.
Keypair:
Par de chaves pública/privada; usado em WireGuard para autenticação.
