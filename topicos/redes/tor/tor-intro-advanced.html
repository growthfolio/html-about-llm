Tor: Anonimato e Onion Routing

Do básico ao avançado — circuitos, hidden services, riscos e defesa em camadas.

Objetivos de Aprendizagem

Ao terminar, você entenderá como Tor funciona (circuitos, camadas de criptografia), reconhecerá seus pontos fracos e saberá combinar Tor com VPN para defesa em camadas.

Resumo Rápido

Tor (The Onion Router) encaminha tráfego através de circuitos de três nós (entry/guard → middle → exit). Cada salto descasca uma camada de cifragem — por isso o nome "onion" — fornecendo anonimato de caminho, mas não imunidade a correlação de tráfego ou leaks do navegador. Use Tor Browser para maior proteção; combine com boas práticas (desativar plugins, evitar login reidentificável).

  • 3 saltos: Guard → Middle → Exit (cada um só sabe vizinhos imediatos).
  • Exit node risk: Tráfego não-HTTPS pode ser lido pelo exit node.
  • Comando útil: curl --socks5-hostname 127.0.0.1:9050 https://check.torproject.org/

Como Tor Funciona: Circuitos de Onion Routing

Tor constrói um caminho (circuito) através de três nós aleatórios da rede Tor: Guard (Entry) → Middle (Relay) → Exit. Cada camada do circuito é criptografada separadamente, como camadas de uma cebola.

Funcionamento passo-a-passo:

  1. Cliente escolhe Guard node: O cliente Tor negocia chaves criptográficas com o Guard. Este nó sabe o IP do cliente, mas não o destino final.
  2. Guard → Middle node: O Guard encaminha para o Middle, que desencapsula uma camada. Middle não sabe a origem real nem o destino final.
  3. Middle → Exit node: O Exit desencapsula a última camada e faz a requisição ao destino final (ex: website). O Exit vê o tráfego não-criptografado (se HTTP) ou criptografado (se HTTPS).
  4. Resposta volta: O processo inverte, cada nó adiciona sua camada de criptografia até voltar ao cliente.

Resultado: Nenhum nó único sabe simultaneamente origem e destino; o anonimato é preservado pela distribuição de conhecimento.

Hidden Services (.onion)

Sites .onion (hidden services) não expõem IP do servidor. Tanto o cliente quanto o servidor constroem circuitos Tor, e se encontram em um ponto intermediário (rendezvous point), garantindo anonimato bidirecional.

Como funciona:

  • O servidor anuncia seu endereço .onion (hash de chave pública) em nós de introdução.
  • Cliente descobre o serviço via diretório Tor.
  • Cliente e servidor negociam um rendezvous point comum na rede Tor.
  • Comunicação ocorre sem que nenhum dos lados revele seu IP real.

Uso comum: Whistleblowing (SecureDrop), mercados anônimos, fóruns de privacidade.

Pontos Fracos e Riscos do Tor

Tor não é infalível. Existem vetores de ataque conhecidos e boas práticas essenciais.

Vulnerabilidades:

  • Exit Node Sniffing: O exit node pode ler tráfego HTTP não-criptografado. Mitigação: Use apenas HTTPS.
  • Traffic Correlation Attacks: Adversário que controla entry e exit pode correlacionar timings de pacotes e identificar usuário. Difícil mas possível para agências estatais.
  • Browser Fingerprinting: JavaScript, WebRTC, plugins podem revelar identidade mesmo via Tor. Mitigação: Use Tor Browser (configurado para resistir fingerprinting).
  • Malformed TLS/SSL Stripping: Exit nodes maliciosos podem tentar downgrade de HTTPS para HTTP. Mitigação: HSTS, Tor Browser alerta sobre cert inválidos.
  • De-anonymization via Login: Se você fizer login em conta real (Gmail, Facebook) via Tor, compromete anonimato. Nunca misture identidades.

Pluggable Transports & Bridges

Em países com censura, ISPs bloqueiam conexões Tor detectando padrões de tráfego. Pluggable Transports disfarçam o tráfego Tor para parecer outro protocolo. Bridges são nós Tor não-listados publicamente, difíceis de bloquear em massa.

Tipos de Pluggable Transports:

  • obfs4: Ofusca tráfego Tor para parecer aleatório, dificulta DPI (Deep Packet Inspection).
  • meek: Tunela tráfego via domínios permitidos (ex: Azure, CloudFront), parecendo tráfego HTTPS normal para CDNs.
  • Snowflake: Usa WebRTC para criar proxies efêmeros em navegadores de voluntários; muito difícil de bloquear.
# Configurar Tor com obfs4 bridge (adicionar em torrc): UseBridges 1 ClientTransportPlugin obfs4 exec /usr/bin/obfs4proxy Bridge obfs4 IP:PORT FINGERPRINT cert=... iat-mode=0 # Obter bridges: https://bridges.torproject.org/

Cenário: Jornalista em país com censura usa Snowflake bridges para acessar Tor sem ser detectado pelo firewall estatal.

Operação Prática do Tor

Usar Tor Browser (recomendado):

Tor Browser é um Firefox modificado, pré-configurado para segurança máxima (NoScript, anti-fingerprinting, isolamento de circuitos por site).

Download: https://www.torproject.org/

Usar Tor como SOCKS5 Proxy:

Tor roda serviço SOCKS5 local em 127.0.0.1:9050. Aplicações podem ser configuradas para usá-lo.

# Instalar Tor (Ubuntu/Debian): sudo apt install tor # Tor inicia automaticamente. Porta padrão: 9050 # Usar com curl: curl --socks5-hostname 127.0.0.1:9050 https://check.torproject.org/ # Usar com torify (wrapper que força SOCKS5): torify curl https://example.com # Configurar app (ex: SSH via Tor): ssh -o ProxyCommand='nc -x 127.0.0.1:9050 %h %p' user@host.onion

Configurar torrc (básico):

# Localização: /etc/tor/torrc (Linux) ou Tor Browser/torrc (Windows/Mac) # Usar bridges (anti-censura): UseBridges 1 Bridge obfs4 ... # Aumentar anonimato (cuidado: mais lento): CircuitBuildTimeout 30 LearnCircuitBuildTimeout 0 # Recarregar config: sudo systemctl reload tor

Tor over VPN vs. VPN over Tor

Combinar Tor e VPN adiciona camada extra de proteção, mas a ordem importa.

Tor over VPN (VPN → Tor)

Você conecta à VPN, depois ao Tor. Seu ISP vê apenas tráfego VPN, não sabe que você usa Tor.

Prós:

  • ISP não sabe que você usa Tor.
  • Útil se Tor é bloqueado/malvisto.

Contras:

  • Provedor VPN vê seu IP real.
  • Exit node ainda vê tráfego.

VPN over Tor (Tor → VPN)

Você conecta ao Tor, depois à VPN. VPN não sabe seu IP real (vê exit node).

Prós:

  • Provedor VPN não sabe seu IP real.
  • Protege contra exit nodes maliciosos.

Contras:

  • Complexo de configurar.
  • Poucos provedores VPN suportam.
  • Performance muito degradada.

Recomendação geral: Para a maioria dos casos, Tor over VPN é mais prático. Para máxima paranoia, use VPN over Tor (ou apenas Tor + Tails).

Cenários de Uso

  • Whistleblowing: Denunciante usa Tor Browser + Tails (OS amnésico) para enviar documentos via SecureDrop sem deixar rastros.
  • Jornalismo Investigativo: Repórter em zona de conflito combina Tor over VPN para pesquisar fontes sensíveis sem revelar localização.
  • Ativismo: Ativista usa Tor + bridges (Snowflake) para contornar censura e organizar protestos de forma segura.
  • Pesquisa de Segurança: Pesquisador acessa fóruns clandestinos (.onion) para estudar malware sem comprometer identidade.

Glossário Rápido

Guard Node (Entry):
Primeiro nó no circuito Tor; sabe seu IP real mas não o destino.
Exit Node:
Último nó; faz requisição ao destino final; pode ver tráfego não-HTTPS.
Bridge:
Nó Tor não-listado publicamente; usado para contornar bloqueios.
Pluggable Transport:
Técnica para disfarçar tráfego Tor (obfs4, meek, Snowflake).
Hidden Service (.onion):
Site acessível apenas via Tor, com IP do servidor oculto.
Tails:
Sistema operacional live (USB/DVD) focado em anonimato, roda Tor por padrão.
