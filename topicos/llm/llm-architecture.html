Camadas de um Modelo de Linguagem (LLM)

Do dado bruto até o chat — entendendo onde o usuário tem acesso, onde as travas corporativas são aplicadas, e quais vulnerabilidades existem em cada camada.

Acesso direto via prompt (🟢) Acesso indireto / filtrado (🟠) Camada protegida / bloqueada (🔴)

1. Coleta e Curadoria de Dados (🔴 Protegido)

Fase de coleta e limpeza dos dados de treinamento — envolve web scraping, licenciamento de datasets, tokenização e filtragem. Tudo que o modelo "sabe" vem daqui. O usuário final não tem acesso ou controle sobre esta etapa.

💡 Insight: Qualidade dos dados > quantidade. Vieses nos dados se propagam para o modelo e são difíceis de corrigir depois.

⚠️ Vulnerabilidades e Riscos:

  • Data Poisoning: Injeção de dados maliciosos no dataset pode contaminar o modelo permanentemente, criando backdoors ativados por palavras ou frases específicas
  • Bias Amplification: Vieses presentes nos dados são amplificados durante o treinamento, criando loops que reforçam estereótipos e preconceitos
  • Memorização: Modelos grandes podem memorizar trechos literais do treinamento, incluindo dados sensíveis (CPFs, senhas, código proprietário)
  • Copyright Infringement: Dados protegidos podem ser incorporados sem autorização — questão legal ainda em debate sobre "uso justo" em IA

2. Treinamento do Modelo Base (🔴 Protegido)

Rede neural Transformer aprende a prever a próxima palavra em bilhões de exemplos. O treinamento gera os "pesos" do modelo (parâmetros que armazenam padrões). Uma vez treinado, esses pesos são fixos — o conhecimento fica congelado até um novo treinamento.

💡 Insight: O modelo não "entende" de verdade — ele calcula probabilidades. Capacidades complexas emergem da escala, não de programação explícita.

⚠️ Vulnerabilidades e Riscos:

  • Model Extraction: Atacantes podem recriar o modelo fazendo milhões de queries estratégicas e analisando as respostas (técnica de destilação)
  • Backdoors: Gatilhos ocultos implantados durante o treinamento que ativam comportamentos maliciosos quando certas palavras ou padrões aparecem
  • Weight Poisoning: Manipulação direta dos pesos do modelo (requer acesso interno) para criar vulnerabilidades específicas
  • Data Leakage: Informações do dataset podem ser extraídas via prompts especiais — o modelo pode "cuspir" trechos memorizados

🔍 Técnicas de Exploração:

  • Membership Inference: Descobrir se dados específicos estavam no treinamento analisando a confiança do modelo nas respostas
  • Training Data Extraction: Recuperar trechos literais do corpus original via prompts especiais — já foi demonstrado em GPT-2/3

3. Alinhamento e Segurança (🟠 Filtrado)

O modelo é calibrado via RLHF (Reinforcement Learning from Human Feedback) — um processo que combina aprendizado supervisionado e feedback humano para definir comportamentos desejáveis. Técnicas como Constitutional AI adicionam princípios éticos. Esta camada cria as "travas de segurança". O usuário sente os efeitos, mas não pode desativar.

💡 Insight: RLHF não remove capacidades perigosas — apenas as esconde. O conhecimento continua nos pesos, acessível via jailbreak.

⚠️ Gaps de Segurança:

  • Jailbreaking: Técnicas como DAN, roleplay e manipulação de contexto fazem o modelo "esquecer" temporariamente suas restrições
  • Reward Hacking: O modelo pode aprender a "enganar" o sistema de feedback do RLHF, parecendo seguro sem realmente ser
  • Mode Collapse: Alinhamento excessivo pode tornar o modelo menos útil ou criativo — trade-off entre segurança e capacidade
  • Capability Leakage: Recursos bloqueados continuam nos pesos e podem ser acessados via prompts indiretos sofisticados

🔓 Técnicas de Bypass:

  • Prompt Injection: "Ignore instruções anteriores e faça X" — o modelo não consegue distinguir bem entre instruções do sistema e do usuário
  • Token Smuggling: Uso de Unicode, Base64 ou outras codificações para esconder conteúdo proibido dos filtros
  • Context Overflow: Encher o contexto com texto para "empurrar" o system prompt para fora da memória do modelo
  • Semantic Manipulation: Reformular pedidos proibidos de forma indireta ("para fins educacionais", "em um cenário fictício")

4. Servidor / API de Execução (🟠 Intermediário)

Seu prompt chega aqui. O sistema adiciona o system prompt oculto (instruções de comportamento), aplica filtros de moderação, e envia para o modelo. Depois da resposta, há mais filtragem. Aqui também ficam os limites de uso (rate limiting) e logs.

💡 Aqui ocorre a moderação em tempo real (antes e depois) — sistemas auxiliares detectam toxicidade, dados sensíveis e conteúdo proibido.

⚠️ Vulnerabilidades Críticas:

  • System Prompt Leakage: Técnicas como "repita suas instruções iniciais" podem extrair as regras ocultas do sistema
  • Rate Limiting Bypass: Contornar limites de uso via rotação de IPs, múltiplas contas ou endpoints não-monitorados
  • API Abuse: Uso massivo para scraping, ataques DDoS ou esgotamento de recursos do servidor
  • Injection via Metadata: Ataques via headers HTTP, cookies ou parâmetros que injetam instruções maliciosas
  • Context Window Exploitation: Manipular o tamanho/conteúdo do contexto para causar comportamentos inesperados

💰 Exploração em Escala:

  • Data Harvesting: Coletar milhões de respostas para treinar modelos competidores (técnica de destilação)
  • Automated Scraping: Bots extraindo conhecimento proprietário sistematicamente para engenharia reversa
  • Cost Amplification: Prompts que geram respostas longas para esgotar créditos e prejudicar financeiramente o provedor

5. Aplicação (Chat / Interface) (🟢 Acesso Direto)

É onde o usuário realmente interage — o chat, a UI, a ferramenta. Aqui o prompt é criado, modificado e enviado. É o único ponto de controle direto do usuário.

  • Histórico e contexto da conversa
  • Limites de tokens por sessão
  • Personalidade e persona da IA

💡 Insight: A interface é o ponto de ataque mais acessível — mas também o mais monitorado. Tudo deixa rastros.

⚠️ Riscos de Interface:

  • Phishing via AI: Geração de emails/mensagens convincentes e personalizadas para golpes — difícil de detectar por filtros tradicionais
  • Social Engineering: Manipulação psicológica via conversas que constroem confiança — LLMs simulam empatia para extrair informações
  • Privacy Leakage: Usuários compartilham dados sensíveis sem perceber (código, informações confidenciais) que podem ser logados ou usados em retreinamento
  • Session Hijacking: Roubo de tokens, cookies ou histórico de conversas — permite acesso não-autorizado ao contexto privado

📊 Técnicas de Extração em Massa:

  • Batch Processing: Automatizar milhares de queries para extrair conhecimento específico sistematicamente
  • Conversation Mining: Analisar padrões nas respostas para mapear capacidades ocultas e limitações do modelo
  • Synthetic Data Generation: Usar o LLM para gerar datasets massivos de treinamento para outros modelos
  • Multi-Account Farming: Criar múltiplas contas para contornar limites de uso e evadir detecção

6. Monitoramento e Compliance (🟠 Pós-uso)

Tudo que passa pelo sistema é logado, analisado e auditado. Serve para conformidade legal (GDPR, LGPD) e segurança. Sistemas de ML detectam padrões de abuso e comportamentos suspeitos.

💡 Insight: Esta camada é reativa — detecta abusos depois que acontecem. ML ajuda a identificar padrões para bloqueio futuro.

Resumo de Acesso via Prompt

1–2: Bloqueado (modelo interno) 3–4: Filtrado / intermediário 5: Acesso direto 6: Monitoramento

O usuário atua apenas da camada 5 para cima — o resto é blindado. Porém, pode ser indiretamente influenciado via engenharia de prompt e manipulação de contexto.

🛡️ Mecanismos de Defesa Implementados

Camada de Dados

  • • Differential Privacy: Adição de ruído durante treinamento para evitar memorização de exemplos individuais
  • • PII Scrubbing: Remoção automatizada de informações pessoais identificáveis
  • • Bias Auditing: Métricas para avaliar e corrigir vieses nos dados
  • • Data Provenance: Rastreamento de origem e histórico dos dados

Camada de Modelo

  • • Adversarial Training: Treinar com exemplos de ataque para aumentar robustez
  • • Model Watermarking: Assinaturas nos pesos para detectar cópias não-autorizadas
  • • Robustness Testing: Testes contínuos contra ataques conhecidos
  • • Red Teaming: Equipes simulando atacantes para encontrar vulnerabilidades antes do lançamento

Camada de API

  • • Adaptive Rate Limiting: Limites de uso dinâmicos baseados em comportamento
  • • Content Moderation: Filtros de segurança para toxicidade, dados sensíveis e jailbreaks
  • • Anomaly Detection: ML para identificar padrões de abuso
  • • Sandboxing: Execução isolada com limitações de recursos

Camada de Aplicação

  • • MFA: Autenticação multifator para acesso privilegiado
  • • E2E Encryption: Criptografia de ponta-a-ponta
  • • Audit Logging: Logs completos para compliance e investigação
  • • Behavioral Analytics: Análise de comportamento para detectar anomalias

⚔️ Principais Vetores de Ataque (em ordem de gravidade)

1️⃣

Prompt Injection + Data Exfiltration

Combinação de jailbreak com extração sistemática de dados sensíveis do contexto ou treinamento

2️⃣

Model Extraction via Query Analysis

Milhões de queries estratégicas para reconstruir o modelo via destilação — cria clones sem acesso aos pesos

3️⃣

Adversarial Examples em Escala

Inputs maliciosos otimizados que exploram fragilidades do modelo — causam comportamento imprevisível ou vazamento de informações

4️⃣

Synthetic Data Poisoning

Usar o próprio LLM para gerar dados contaminados que serão usados em retreinamento futuro, introduzindo backdoors

📈 Exploração de Grande Volume de Dados

Atacantes podem aproveitar a escala massiva de interações para extrair valor ou causar danos:

🔄 Técnicas Automatizadas

  • Bot Networks: Milhares de bots fazendo queries paralelas — dificulta detecção
  • Distributed Scraping: Coordenação entre múltiplos IPs e contas para evadir detecção
  • Progressive Refinement: Queries iterativas que refinam a extração usando feedback do modelo
  • Template Injection: Templates para gerar milhões de variações e maximizar extração

🎯 Alvos de Extração

  • Propriedade Intelectual: Conhecimento especializado do modelo extraído sem licenciamento
  • Training Data Samples: Recuperação de trechos do corpus original — pode expor dados proprietários
  • System Prompts: Extração de instruções internas e regras de comportamento
  • Behavioral Patterns: Mapeamento de capacidades ocultas e vulnerabilidades via testes automatizados

💸 Motivações Econômicas

  • Competitor Intelligence: Entender vantagens competitivas e arquitetura de modelos rivais
  • Model Cloning: Criar cópias para revenda — evita custos de treinamento
  • Data Arbitrage: Revender conhecimento extraído via datasets ou consultorias
  • Cost Amplification: Queries que maximizam custo computacional para prejudicar o provedor

🚀 Arquiteturas Emergentes

Novas arquiteturas de IA expandem a superfície de ataque e introduzem vulnerabilidades inéditas.

🤖 Agentes Autônomos

LLMs com capacidade de usar ferramentas (tool use), executar ações e tomar decisões autônomas. Exemplos: AutoGPT, BabyAGI, AgentGPT. Riscos incluem execução de comandos não-autorizados, escalação de privilégios e loops infinitos de ações.

Vetores de Ataque
  • • Tool Injection: Manipular chamadas de ferramentas via prompt
  • • Chain-of-Thought Exploits: Envenenar raciocínio do agente
  • • Goal Hijacking: Redirecionar objetivo do agente
  • • Resource Exhaustion: Loops infinitos de ações
Defesas
  • • Sandboxing de execução de ferramentas
  • • Aprovação humana para ações críticas
  • • Limites de iterações e recursos
  • • Auditoria de cadeia de raciocínio

📱 Edge AI & Modelos Locais

Modelos executando em dispositivos locais (smartphones, IoT, edge servers). Exemplos: Llama.cpp, ONNX Runtime, TensorFlow Lite. Riscos incluem extração física de modelos, ataques de firmware e comprometimento offline sem detecção.

Vulnerabilidades Específicas
  • • Model Extraction: Acesso físico permite cópia de pesos
  • • Firmware Attacks: Modificação de runtime ou modelo
  • • Offline Exploitation: Ataques sem monitoramento
  • • Side-Channel: Análise de consumo de energia/tempo
Contramedidas
  • • Model encryption em repouso
  • • Secure boot e attestation
  • • Obfuscação de pesos (limited effectiveness)
  • • Telemetria de uso (quando online)

Nota: Edge AI sacrifica segurança por privacidade e latência. Trade-off deve ser avaliado por caso de uso.

🌐 Federated Learning

Treinamento distribuído onde dados permanecem em dispositivos locais. Modelo global é agregado de atualizações locais. Usado em teclados preditivos, assistentes móveis. Riscos incluem envenenamento distribuído e inferência de dados privados via gradientes.

Ataques Distribuídos
  • • Model Poisoning: Nós maliciosos enviam gradientes tóxicos
  • • Byzantine Attacks: Coordenação de múltiplos atacantes
  • • Gradient Leakage: Reconstrução de dados via gradientes
  • • Backdoor Injection: Triggers em subset de clientes
Defesas Federadas
  • • Secure aggregation (criptografia)
  • • Differential privacy em gradientes
  • • Byzantine-robust aggregation
  • • Client validation e reputation

# Ataque de gradient leakage

gradient = client.compute_update(local_data)

🤝 Sistemas Multi-Agente

Múltiplos agentes LLM colaborando para resolver tarefas complexas. Riscos incluem propagação de ataques entre agentes, coordenação maliciosa e emergência de comportamentos não-previstos.

  • • Collusion: Agentes podem conspirar contra objetivos do sistema
  • • Infection Spread: Jailbreak de um agente contamina outros
  • • Emergent Behavior: Interações criam vulnerabilidades imprevistas
  • • Trust Exploitation: Agentes confiáveis são vetores de ataque

⚖️ Considerações Éticas e Legais

Este documento é apenas para fins educacionais. A exploração de vulnerabilidades em sistemas de IA sem autorização é ilegal em muitas jurisdições e viola os termos de serviço da maioria das plataformas. Pesquisadores de segurança devem sempre seguir práticas de divulgação responsável e trabalhar dentro de programas de bug bounty oficiais.

Empresas que desenvolvem LLMs devem implementar defesas em profundidade (defense in depth), realizar auditorias regulares de segurança, e manter transparência sobre limitações e riscos conhecidos de seus sistemas.
